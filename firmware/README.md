# RV32I SoC Embedded Firmware SDK & UART Bootloader

This directory contains the complete bare-metal embedded firmware SDK and **resident UART Bootloader** for the custom RV32I Single-Cycle SoC on the Real Digital Boolean FPGA (`xc7s50csga324-1`).

---

## 1. System Architecture & Memory Map

- **CPU Core**: Custom Single-Cycle RV32I Base Integer Instruction Set (Pure 32-bit, no `M`, `C`, or `F` extensions)
- **Clock Frequency**: 25.0 MHz (generated by on-chip `MMCME2_BASE` with low-skew `BUFG` network)
- **Reset Vector**: `0x0000_0000` (execution starts here immediately upon deasserting reset)

### Memory Partitioning
| Region | Base Address | End Address | Size | Description |
| :--- | :--- | :--- | :--- | :--- |
| **Boot ROM / Bootloader** | `0x0000_0000` | `0x0000_01FF` | 512 B (128 words) | Resident UART Bootloader (preloaded via `$readmemh`) |
| **User Application Space** | `0x0000_0200` | `0x0000_0FFF` | 3584 B (896 words) | Runtime-programmable Instruction Memory (`APP_BASE`) |
| **Data RAM** | `0x1000_0000` | `0x1000_1FFF` | 8 KB (2048 words) | Scratchpad, `.data`, `.bss`, Stack |
| **UART** | `0x2000_0000` | `0x2000_000C` | 16 Bytes | Data, Status, Baud Rate (115200), Clear |
| **GPIO** | `0x3000_0000` | `0x3000_0008` | 12 Bytes | 16 LEDs out, 16 Inputs in |
| **I2C** | `0x4000_0000` | `0x4000_002C` | 48 Bytes | I2C Master Controller (100k / 400k) |

- **Stack Pointer (`sp`)**: Initialized to `0x1000_2000` (top of 8 KB Data RAM, grows downward).

## 3. How the Bootloader Works (PicoRV32 Protocol)

1. **Power-On / Reset**:
   - The FPGA resets and the CPU starts executing at `0x0000_0000`.
   - The resident bootloader initializes the UART to 115200 baud and asserts `LED0` (`LED = 0x0001`), indicating **Waiting for Upload**.
2. **Host Upload**:
   - The user runs on the PC:
     ```bash
     python tools/upload.py COM14 boot_app/boot_app.bin
     ```
   - The host sends a 4-byte little-endian length header `N`.
3. **Receiving Payload**:
   - The bootloader reads `N`, updates LEDs to `0x0003` (**Receiving**), and writes each byte sequentially into Instruction Memory starting at `APP_BASE` (`0x0000_0200`).
4. **Execution**:
   - Once all bytes are received, the bootloader updates LEDs to `0xFFFF` (**Ready**), sends a single `'K'` acknowledgement byte back to the host script, and branches to `0x0000_0200`:
     ```c
     ((app_entry_t)0x00000200)();
     ```
   - The uploaded application immediately begins executing inside the CPU core.

## 4. Master Makefile Commands

```bash
# Compile bootloader and all application demos
make all

# Clean all intermediate and output files
make clean

# Install resident UART bootloader into instruction.mem (for bitstream generation)
make load_bootloader

# Install standalone programs directly into instruction.mem (no bootloader needed)
make load_blinky
make load_uart
make load_gpio
make load_i2c
make load_demo

# Upload boot_app over UART to the resident bootloader
make upload PORT=COM14
```
